1. STAR-LDM: Hybrid Diffusion + AR

STAR-LDM (COLM 2025) combines latent diffusion planning with autoregressive generation to produce higher-quality text than pure AR models.

The noised 768-dim sentence embedding zt is split into 8 soft-prompt tokens (1280-dim) by the Soft Prompt Generator, fed through GPT-2 Large alongside cached prefix KV, then the ScoreNet Head predicts the v-target for a DDPM denoising update. This repeats T=50 times.

3. AutoRegress: Final soft prompts condition GPT-2 for token-by-token text generation.

The Problem

Each diffusion step invokes the full 770M-param GPT-2 backbone. At 50 steps, this makes STAR-LDM ~2.3x slower than GPT-2 Large alone, despite producing better text. The authors note their implementation is "not optimized for inference speed."

2. Profiling: Where Does Time Go?

Profiled on 50 C4 prompts (M4 Max, 50 steps, unoptimized). GPT-2 accounts for 77.2% of total inference time (38.7% diffusion loop + 38.5% AR generation).

The Real Bottleneck: Dispatch Overhead

Using torch.profiler, we count 6,185 ATen operator dispatches per v-prediction call. Only 432 (7%) perform computation. The rest: attention mask construction, cache management, tensor reshaping, type checking.

At ~3.4μs per dispatch, framework overhead alone accounts for ~21ms per call, matching measured latency.

Roofline Analysis

Micro-transformer ops (RMSNorm, attention on 8 tokens) achieve <1% of the M4 Max roofline ceiling. Not compute-bound, not memory-bound: dispatch-latency-bound.

3. Optimizations

A. Streamlined GPT-2 Forward

Replace HuggingFace's GPT2LMHeadModel.forward() with 40 lines of PyTorch that perform only the essential computation:

  • Eliminate attention mask construction (72 dispatches)
  • Remove DynamicCache management overhead
  • Skip tensor format conversions and view ops
  • Use F.linear directly on layer weights

Reduces dispatches from 6,185 → 432 per call. 3.6x faster on the component that is 70% of runtime.

B. KV-Cache with Pre-Allocated Buffers

Compute prefix KV projections once, reuse across all diffusion steps. Pre-allocate contiguous (prefix_len + 8) buffers for each of 36 layers. The naive torch.cat approach allocates 1,800 new tensors per generation, causing 10x slowdown on long prefixes. Pre-allocation eliminates all allocation from the diffusion loop.

Per-step cost: O(1) vs O(prefix_len) baseline.

5. Future Work (Final Report)

A. Cross-Platform CUDA Comparison

Run the identical benchmark suite on NVIDIA A100 (CUDA/Triton) to test whether our findings generalize:

  • Does the streamlined forward help on CUDA, or is framework overhead MPS-specific?
  • Does torch.compile with CUDA Graphs succeed where MPS failed?
  • How do Metal kernel speedups compare to Triton equivalents?

Expected: CUDA Graphs should reduce dispatch overhead more effectively than our manual approach. The comparison isolates which bottlenecks are hardware-specific vs framework-specific.

B. Quality Validation

Generate 5,000 C4 continuations with both pipelines. Compute MAUVE and perplexity to verify optimizations preserve output quality.

Critical because our fast forward drops causal masking on the 8 soft prompts. The SPG generates them non-causally, so this may be correct, but needs empirical validation.

C. Model Scheduling

Profile v-prediction error at each noise level. Hypothesis: at early (high noise) and late (low noise) steps, GPT-2 adds minimal value. Replace it with cheap SPG+ScoreNet-only path (~3ms vs ~12ms/step) at "easy" steps.

Training-free. Could reduce diffusion loop cost by 30-40%.

D. Consistency Distillation (Stretch)

Train a student score network to map zt → z0 in 1-4 steps instead of 50, following LCM (Luo et al., 2024). STAR-LDM's 768-dim embedding space is much smoother than pixel space, suggesting few-step distillation should be effective.

At 4 steps: diffusion loop drops from ~600ms to ~50ms. Total pipeline: ~550ms (faster than GPT-2 Large with better quality).

Key Takeaway

For hybrid diffusion-AR models, the primary inference bottleneck is framework dispatch overhead, not GPU kernel performance.

HuggingFace's GPT-2 issues 14x more operator dispatches than needed. A 40-line PyTorch rewrite that strips framework abstractions gives a larger speedup (3.6x on 70% of the pipeline) than six custom Metal GPU kernels combined.

Roofline analysis reveals a dispatch-latency-bound regime where micro-transformer operations achieve <1% of hardware ceiling. Custom kernels help for non-GEMM ops (1.7-2.4x) but cannot beat Apple's BLAS for matrix multiplications.
